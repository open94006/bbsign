# 賽事路線與海拔圖：可行性評估與計劃書

2026-10-14（同日改版：顯示改用第三方嵌入，試點 15 場半馬以上賽事；P1、P2 已完成，尚未部署）

## 1. 結論

**可行，而且程式量很小。成本幾乎都在整理路線。**

- **顯示交給第三方**：
  - [Ride with GPS](https://ridewithgps.com) 的嵌入頁本身就有地圖加海拔圖，公里、公尺，手機可用。
  - 已實測：主辦單位放上去的日月潭、蘆洲觀音山路線，直接嵌入就能看，不用登入。
  - 我們只要寫「路線圖」按鈕、彈窗和各距離切換鈕，約半天。
  - 原本規劃的海拔資料處理、Leaflet、自己畫海拔圖全部不用做。
- **試點 15 場半馬以上的賽事，共 52 條路線**（每個距離一條）：
  - 5 場主辦單位已有線上路線，17 條可以直接嵌入。
  - 其餘 35 條要照官方路線圖，在 Ride with GPS 描出來，約 15–18 小時。
- **「超過一千人」不必寫進程式**：
  - 能從頁面看出名額的半馬以上賽事，88% 都超過一千人。
  - 最大的幾場反而查不到名額。
  - 範圍改用「半馬以上」，現有的距離欄位就能判斷。

## 4. 設計

### 4.1 資料：`events` 加一欄

```sql
alter table events add column if not exists routes jsonb;
-- [{"label": "全馬", "url": "https://ridewithgps.com/embeds?type=route&id=…&metricUnits=true&sampleGraph=true"}, …]
```

- 爬蟲的 upsert 只寫固定欄位，管理頁存檔也只寫 `EventIn` 的欄位，所以這欄不會被覆蓋，也不會把賽事鎖定。
- 資料寫在 `backend/routes.sql`。每次啟動時 `db.init()` 會接在 `schema.sql` 後面重跑它，再清掉 `bb:events` 快取，所以改檔、部署就生效，不用手動連正式資料庫。
- 用「比賽日＋名稱關鍵字」對賽事，不用 id，原因有兩個：
  - 本機資料庫是 localhost，id 和正式站不同。
  - 同一場在不同來源的卡片會一起對到，例如新竹城市、渣打各有兩筆。
- 存完整的嵌入網址，前端直接放進 iframe，不必知道是哪家服務。Garmin 的格式是 `https://connect.garmin.com/embed/course/<id>`。

### 4.2 網站

| 檔案                                        | 改動                                                                                                                                                           |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `backend/schema.sql`、`routes.sql`、`db.py` | 上面那一欄；路線資料；啟動時重跑 `routes.sql` 並清快取                                                                                                         |
| `backend/main.py`                           | `PUBLIC` 查詢多選 `routes`；CSP 加 `frame-src https://ridewithgps.com https://connect.garmin.com`；`POST /api/route-view` 回 204（量測用，見下）               |
| `frontend/src/data.ts`                      | `RaceEvent` 加 `routes: { label: string; url: string }[] \| null`                                                                                              |
| `frontend/src/RaceRow.tsx`                  | 有 `routes` 才出現「路線圖」按鈕。點了開原生 `<dialog>`：標題、距離切換鈕、iframe、註記、關閉。iframe 在打開時才設定 `src`，沒點的人不會載入第三方。手機全螢幕 |

彈窗用原生 `<dialog>`：Esc 關閉、焦點鎖定、背景遮罩都是瀏覽器內建，不用另裝套件。

**量測**：打開彈窗時送一個 `POST /api/route-view?id=<賽事 id>`，後端直接回 204，次數從 Cloud Run 請求紀錄數。地圖本身在第三方網站，我們的伺服器看不到，所以需要這一行。

## 6. 風險

| 風險                             | 處理                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------- |
| Ride with GPS 改掉或收掉免費嵌入 | 我們描的路線在自己帳號裡可以匯出 GPX，必要時換 gpx.studio 嵌入（3.4 備案）   |
| 描線耗時超出預估                 | P3 每場記時間；平均超過 1.5 小時／場就只做全馬、半馬                         |
| 路線錯誤誤導跑者                 | 路線名稱寫年份；彈窗註明以大會公告為準；描出來的距離差超過 2% 就重描         |
| 第三方 iframe 的隱私與載入       | 按了按鈕才載入；不放任何追蹤參數                                             |
| 一個人維護不來                   | 整季約 100 場、每場 1–1.5 小時，旺季每週約 3–5 小時。P4 用試點的實際數字決定 |
